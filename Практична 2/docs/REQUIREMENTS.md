# Вимоги до проєкту «Погода поруч»
Версія: 1, дата: 24.10.2026

## Функціональні вимоги

### US-1. Введення міста
Як користувач віджета, я хочу ввести назву міста, щоб отримати прогноз погоди для потрібного місця.

**Критерій 1.**
- Given: віджет відкритий, поле міста порожнє.
- When: користувач вводить «Київ» і натискає «Показати погоду».
- Then: віджет починає пошук погоди для міста «Київ».

**Критерій 2.**
- Given: поле міста порожнє.
- When: користувач натискає «Показати погоду».
- Then: віджет показує повідомлення «Введіть назву міста» і не надсилає порожній запит.

### US-2. Пошук прогнозу
Як користувач віджета, я хочу отримати дані про погоду з відкритого API, щоб бачити актуальний прогноз.

**Критерій 1.**
- Given: у полі введено «Київ» і API доступний.
- When: користувач запускає пошук.
- Then: віджет показує результат для «Київ».

**Критерій 2.**
- Given: API не відповідає.
- When: користувач шукає погоду для «Львів».
- Then: віджет показує повідомлення про тимчасову недоступність даних, а не порожній результат.

### US-3. Перегляд поточної погоди
Як користувач віджета, я хочу бачити поточну температуру й опис погоди, щоб оцінити умови в місті.

**Критерій 1.**
- Given: API повернув для «Київ» температуру 18 °C і опис «Хмарно».
- When: пошук завершився успішно.
- Then: віджет показує «18 °C» і «Хмарно».

**Критерій 2.**
- Given: API не повернув температуру для міста «Київ».
- When: віджет відображає результат.
- Then: замість числа відображається повідомлення «Температура недоступна».

### US-4. Перегляд прогнозу на 5 днів
Як користувач віджета, я хочу переглянути прогноз на найближчі 5 днів, щоб планувати справи наперед.

**Критерій 1.**
- Given: API повернув прогноз на 5 днів для «Львова».
- When: користувач переглядає результат пошуку.
- Then: віджет показує 5 окремих дат із даними прогнозу.

**Критерій 2.**
- Given: API повернув дані лише на 3 дні.
- When: віджет показує прогноз.
- Then: відображаються тільки 3 доступні дні без вигаданих даних для решти.

### US-5. Перегляд погоди після зміни міста
Як користувач віджета, я хочу шукати погоду в іншому місті, щоб порівнювати умови в різних місцях.

**Критерій 1.**
- Given: на екрані вже показано погоду для «Києва».
- When: користувач вводить «Одеса» і запускає пошук.
- Then: віджет показує новий результат для «Одеси».

**Критерій 2.**
- Given: показано погоду для «Києва».
- When: пошук міста «Невідомоград» не знаходить результатів.
- Then: віджет повідомляє, що місто не знайдене, і не показує старі дані як прогноз для нового міста.

### US-6. Оновлення прогнозу
Як користувач віджета, я хочу повторно завантажити прогноз, щоб отримати найновіші доступні дані.

**Критерій 1.**
- Given: для «Києва» вже показано прогноз.
- When: користувач натискає «Оновити».
- Then: віджет надсилає новий запит і показує отримані дані.

**Критерій 2.**
- Given: запит оновлення триває.
- When: користувач натискає «Оновити» повторно.
- Then: віджет не запускає паралельні повторні запити та показує стан завантаження.

### US-7. Повідомлення про невідоме місто
Як користувач віджета, я хочу отримати зрозуміле повідомлення для невідомого міста, щоб виправити запит.

**Критерій 1.**
- Given: у поле введено «Невідомоград», якого немає у відповіді API.
- When: користувач запускає пошук.
- Then: віджет показує «Місто не знайдено. Перевірте назву».

**Критерій 2.**
- Given: раніше успішно показувалася погода для «Києва».
- When: пошук «Невідомограда» завершується помилкою.
- Then: попередній прогноз не позначається як результат для «Невідомограда».

### US-8. Відображення одиниць температури
Як користувач віджета, я хочу бачити температуру в градусах Цельсія, щоб зрозуміти прогноз у звичному форматі.

**Критерій 1.**
- Given: API повернув температуру 18 градусів Цельсія.
- When: віджет показує поточну погоду.
- Then: температура відображається як «18 °C».

**Критерій 2.**
- Given: API не повернув одиницю вимірювання.
- When: віджет показує температуру.
- Then: віджет використовує позначення «°C», визначене налаштуванням запиту, або повідомляє, що дані недоступні.

## Нефункціональні вимоги
- НФ-1. За стабільного з’єднання відповідь віджета з’являється не довше ніж за 5 с. Перевірка: 5 запитів до доступного API із секундоміром.
- НФ-2. На екрані шириною 360 пікселів немає горизонтальної прокрутки. Перевірка: відкрити сторінку в режимі мобільного пристрою шириною 360 px.
- НФ-3. Основний текст має розмір не менше 16 px, а контраст тексту й фону – не менше 4,5:1. Перевірка: інструменти розробника та калькулятор контрасту.
- НФ-4. Повідомлення про помилку зрозуміле без технічного коду та містить коротку пораду користувачу. Перевірка: 3 користувачі мають пояснити, що робити після помилки.
- НФ-5. Віджет обробляє щонайменше 5 послідовних пошуків міст без перезавантаження сторінки. Перевірка: послідовно шукати «Київ», «Львів», «Одеса», «Харків» і «Дніпро».
