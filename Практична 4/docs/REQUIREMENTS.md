# Вимоги до проєкту «Погода поруч»
Версія: 3, дата: 07.11.2026

## Функціональні вимоги

### US-1. Пошук міста
Як користувач віджета погоди, я хочу ввести назву міста, щоб побачити прогноз для потрібного місця.

**Критерій 1.**
- Given: віджет відкритий, поле міста порожнє.
- When: користувач вводить «Київ» і починає пошук.
- Then: віджет надсилає запит для міста «Київ».

**Критерій 2.**
- Given: поле міста порожнє.
- When: користувач починає пошук.
- Then: віджет показує «Введіть назву міста» і не надсилає порожній запит.

### US-2. Перегляд поточної погоди
Як користувач віджета погоди, я хочу переглянути поточну погоду, щоб оцінити умови у вибраному місті.

**Критерій 1.**
- Given: API повернув для «Києва» температуру 18 °C і опис «Хмарно».
- When: пошук міста завершився успішно.
- Then: віджет показує «18 °C» і «Хмарно».

**Критерій 2.**
- Given: API не повернув температуру для «Києва».
- When: віджет відображає результат пошуку.
- Then: віджет показує «Температура недоступна» замість вигаданого числа.

### US-3. Перегляд прогнозу на найближчу добу
Як користувач віджета погоди, я хочу переглянути прогноз на найближчу добу, щоб планувати справи на завтра.

**Критерій 1.**
- Given: API повернув для «Львова» прогноз на завтра з температурою 17 °C та описом «Хмарно».
- When: користувач переглядає прогноз.
- Then: віджет показує дату, «17 °C» і «Хмарно».

**Критерій 2.**
- Given: API не повернув прогноз для «Львова» на найближчу добу.
- When: віджет відображає прогноз.
- Then: віджет показує «Прогноз недоступний» і не вигадує дані.

### US-4. Зміна міста
Як користувач віджета погоди, я хочу знайти погоду в іншому місті, щоб переглянути умови в потрібному місці.

**Критерій 1.**
- Given: віджет показує погоду для «Києва».
- When: користувач вводить «Одеса» й починає пошук.
- Then: віджет показує нові дані та назву міста «Одеса».

**Критерій 2.**
- Given: віджет показує результат для «Києва».
- When: користувач замінює назву міста на «Львів» і починає пошук.
- Then: результат для «Львова» замінює результат для «Києва».

### US-5. Ручне оновлення прогнозу
Як користувач віджета погоди, я хочу оновити прогноз, щоб отримати найновіші доступні дані.

**Критерій 1.**
- Given: для «Києва» вже показано прогноз.
- When: користувач натискає «Оновити».
- Then: віджет надсилає новий запит для «Києва» й показує отримані дані.

**Критерій 2.**
- Given: запит оновлення для «Києва» ще виконується.
- When: користувач повторно натискає «Оновити».
- Then: віджет не запускає паралельний запит і показує стан завантаження.

### US-6. Повідомлення про невідоме місто
Як користувач віджета погоди, я хочу дізнатися, що місто не знайдено, щоб виправити назву.

**Критерій 1.**
- Given: введено назву «Невідомоград», якої немає у відповіді API.
- When: користувач починає пошук.
- Then: віджет показує «Місто не знайдено. Перевірте назву».

**Критерій 2.**
- Given: після невдалого пошуку в полі введено «Невідомоград».
- When: користувач замінює назву на «Київ» і починає пошук.
- Then: віджет прибирає повідомлення про помилку й показує прогноз для «Києва».

### US-7. Повідомлення про недоступність погодних даних
Як користувач віджета погоди, я хочу побачити повідомлення про недоступність погодних даних, щоб знати, що запит треба повторити пізніше.

**Критерій 1.**
- Given: користувач шукає погоду для «Львова», але API не відповідає.
- When: запит завершується помилкою з’єднання.
- Then: віджет повідомляє про тимчасову недоступність даних і пропонує повторити запит.

**Критерій 2.**
- Given: попередній запит для «Львова» завершився помилкою, а API знову доступний.
- When: користувач повторює пошук «Львів».
- Then: віджет показує отриманий прогноз і прибирає повідомлення про недоступність.

### US-8. Визначення місця перебування (поза MVP)
Як користувач віджета погоди, я хочу дозволити визначення місця перебування, щоб не вводити місто вручну.

**Критерій 1.**
- Given: користувач надав дозвіл на визначення місця перебування.
- When: користувач запускає визначення місця.
- Then: віджет показує погоду для визначеного місця.

**Критерій 2.**
- Given: користувач відмовив у дозволі на визначення місця перебування.
- When: віджет запитує місце перебування.
- Then: віджет пояснює, що дозвіл не надано, і залишає ручне введення міста доступним.

### US-9. Збереження обраного міста (поза MVP)
Як користувач віджета погоди, я хочу зберегти місто в обране, щоб швидко повернутися до його прогнозу.

**Критерій 1.**
- Given: для «Одеси» успішно показано погоду.
- When: користувач додає «Одесу» до обраного.
- Then: «Одеса» з’являється у списку обраних міст.

**Критерій 2.**
- Given: «Одеса» вже є у списку обраних міст.
- When: користувач повторно додає «Одесу» до обраного.
- Then: у списку залишається один запис «Одеса».

### US-10. Перегляд прогнозу на 5 днів (поза MVP)
Як користувач віджета погоди, я хочу переглянути прогноз на 5 днів, щоб планувати справи наперед.

**Критерій 1.**
- Given: API повернув прогноз для «Львова» на 5 дат.
- When: користувач переглядає розширений прогноз.
- Then: віджет показує 5 дат із відповідними даними.

**Критерій 2.**
- Given: API повернув дані для «Львова» лише на 3 дні.
- When: віджет відображає розширений прогноз.
- Then: віджет показує лише 3 доступні дні й не вигадує дані для решти.

## Нефункціональні вимоги
- НФ-1. За стабільного з’єднання результат пошуку з’являється не довше ніж за 5 с. Перевірка: виконати 5 запитів до доступного API та виміряти час секундоміром.
- НФ-2. На екрані шириною 360 px немає горизонтальної прокрутки. Перевірка: відкрити сторінку в режимі мобільного пристрою шириною 360 px.
- НФ-3. Основний текст має розмір не менше 16 px, а контраст тексту й фону – не менше 4,5:1. Перевірка: виміряти розмір тексту в інструментах розробника й перевірити контраст калькулятором контрасту.
- НФ-4. Щонайменше 3 з 3 користувачів без підказки розуміють повідомлення про помилку й можуть сказати, що робити далі. Перевірка: дати трьом користувачам виконати пошук неіснуючого міста та зафіксувати їхні відповіді.
- НФ-5. Віджет обробляє 5 послідовних пошуків без перезавантаження сторінки. Перевірка: послідовно шукати «Київ», «Львів», «Одеса», «Харків» і «Дніпро».
